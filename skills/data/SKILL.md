# data (데이터 점검)

원본 파일은 수정하지 않는다. 모든 분석은 analysis/ 폴더의 스크립트로 남겨 다시 실행할 수 있게 한다.

1. 먼저 사용자에게 묻는다: "이 데이터로 무엇을 확인하고 싶나요? 예상하는 결과가 있나요?"
2. 구조 파악: 파일 목록, 행·열 수, 각 열의 의미와 단위, 기간, 분석 단위(로트·웨이퍼·다이·설비·사람 등).
   열의 의미를 모르면 추측하지 말고 "담당자에게 물을 것"으로 남긴다.
3. 함정 점검 (각 항목 1줄로 결과 보고):
   - 결측·이상값: 어느 열에 얼마나
   - 불균형: 목표 값(불량 등)의 비율
   - 누수: 결과를 알고 나서야 생기는 열이 입력에 섞여 있는지
   - 시간 순서: 미래 정보가 과거 판단에 쓰이지 않는지
   - 중복·키: 같은 대상이 여러 번 있는지
4. 기준선: 가장 단순한 방법(평균, 규칙 하나, 다수 클래스 등)의 성능을 먼저 계산한다.
   지표는 문제에 맞게 고르고 이유를 쓴다. 불균형이면 정확도 대신 검출률·오탐률을 쓴다.
5. 결과를 DECISIONS에 기록한다: 발견한 함정, 기준선 수치, 고른 지표와 이유.
   데이터로 확인 못 한 전제는 가정 표에.
6. 마지막에 "이 데이터로 답할 수 있는 질문 / 답할 수 없는 질문"을 각 2개씩 정리해 사용자에게 보여준다.
