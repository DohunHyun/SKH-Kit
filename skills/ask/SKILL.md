# ask (질문)

1. 사용자에게 먼저 묻는다: "담당자에게 가장 먼저 확인하고 싶은 것 하나는 무엇인가요?"
2. README와 지금까지의 PLAN·가정 표를 보고, 아직 모르는 것을 렌즈별로 질문 후보로 만든다. 렌즈당 최대 2개.
   - 현재 방식: 지금은 어떻게 하는지, 얼마나 걸리는지
   - 가장 아픈 지점: 어느 단계가 가장 오래 걸리거나 답답한지
   - 결과 사용자: 결과를 받아서 누가 무엇을 결정하는지
   - 비용 비대칭: 놓치는 것과 헛경보 중 무엇이 더 비싼지
   - 실패 사례: 지금 방식이 특히 실패하는 경우
   - 당연함: 이 방식을 쓰는 이유가 있는지, 원래 그래왔던 건지
   질문은 해법을 암시하지 않는 열린 질문으로 쓴다. ("AI로 하면 어떨까요?" 금지)
3. 후보를 번호로 보여주고 사용자가 3~4개를 고르게 한다. 순서는 사소한 사실 → 사례 → 예외 → 성공 기준.
4. 사용자가 담당자 답변을 붙여넣으면:
   - 담당자가 실제로 한 말만 PLAN에 반영한다. 지어내지 않는다.
   - 해결된 가정은 가정 표에서 "확인됨"으로 바꾼다.
   - 답변에서 새로 생긴 의문을 다음 질문 후보로 1~2개 제안한다.
