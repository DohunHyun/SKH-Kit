# pitch (피칭)

PLAN, DECISIONS, FLOW와 검증 기록만 근거로 쓴다. 확인하지 않은 효과를 말하지 않는다.

1. 먼저 사용자에게 묻는다: "심사위원이 꼭 기억했으면 하는 한 문장은 무엇인가요?"
2. 3분 뼈대를 docs/PITCH.md에 만든다. 각 칸은 2~3줄, 말하는 문장이 아니라 키워드로.
   - 문제 (30초): 현장의 누가, 무엇 때문에, 얼마나 곤란한가
   - 다시 정의한 지점 (40초): 당연하게 여기던 방식 중 무엇을 다르게 봤는가, 왜
   - 해결 (40초): 무엇을 만들었고 사람과 AI가 각각 무엇을 하는가
   - 증거 (40초): 기준선 대비 효과, 어떻게 확인했는가
   - 한계와 다음 단계 (30초): 확인 못 한 것, 현장 적용 전 필요한 것
3. 시연한다면 보여줄 화면 순서를 3단계로 적는다.
4. 예상 질문 5개와 답변 키워드를 붙인다: 데이터 출처, 보안, 현장 적용, 기준선 비교, 실패 사례.
5. 사용자에게 소리 내어 한 번 말해보라고 권하고, 막힌 칸을 함께 다듬는다.
